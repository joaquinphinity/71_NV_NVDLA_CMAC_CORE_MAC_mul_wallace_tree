HINTS FOR WALLACE TREE IMPLEMENTATION

NOTE: These hints are for reference after your first attempt. Try solving the task first by analyzing the codebase, then consult these if needed.


HINT 1: Where to Start

The CSA trees you need to replace are instantiated in NV_NVDLA_CMAC_CORE_MAC_mul.v. Search for "NV_DW02_tree" to find them. There are three instantiations total - two for Level 0 (5-input trees) and one for Level 1 (4-input tree).


HINT 2: Understanding the Interface

Look at how NV_DW02_tree is instantiated. The interface pattern is:
  - INPUT: A wide concatenated vector containing all inputs packed together
  - OUT0: First output (sum)
  - OUT1: Second output (carry)

Your Wallace tree modules should match this same interface pattern.


HINT 3: Unpacking Concatenated Inputs

The INPUT signal packs multiple values together. The format is INPUT = {input[N-1], ..., input[1], input[0]} with input[0] in the LSBs. You'll need to unpack this into individual signals before feeding them to your CSA stages.


HINT 4: CSA32 Implementation

The 3:2 compressor logic translates to:
  - sum = in0 XOR in1 XOR in2 (bitwise)
  - carry = majority function, left-shifted by 1 bit
  - Majority = (in0 AND in1) OR (in1 AND in2) OR (in0 AND in2)
  - Left shift means carry[i] comes from majority of inputs at bit position [i-1]


HINT 5: Wallace Tree Topology

For 5 inputs, you need multiple CSA stages. One efficient approach:
  - First CSA: reduce first 3 inputs to 2
  - Second CSA: take those 2 outputs plus one more input (now 3 again) to get 2
  - Third CSA: take those 2 outputs plus the last input to get final 2

That's 3 levels total for 5→2 reduction.


HINT 6: Level 1 Tree (4 inputs)

For 4 inputs, you need fewer stages:
  - First CSA: reduce first 3 inputs to 2
  - Second CSA: take those 2 outputs plus the 4th input to get final 2

That's 2 levels for 4→2 reduction.


HINT 7: Parameterization

Use parameter WIDTH (or similar) in your CSA module so it can handle both 24-bit (Level 0) and 32-bit (Level 1) operations. Look at how NV_DW02_tree uses parameters: #(5, 24) means 5 inputs of 24 bits each.


HINT 8: INT8 Mode

In INT8 mode, the two Level 0 trees operate completely independently (dual 8×8 multiplication). Level 1 is bypassed. Make sure your Level 0 Wallace trees don't share any signals - they should be truly independent instances.


HINT 9: Signal Names

The output signals from the CSA trees are used downstream (pp_out_l0n0_0, pp_out_l0n0_1, etc.). Keep these exact names when you replace the tree instantiations, or the output mux logic will break.


HINT 10: What NOT to Change

Don't modify:
  - Booth encoding logic (it's complete and working)
  - Partial product construction (the ppre_0 through ppre_9 logic)
  - Config registers or mode selection logic
  - Output mux (res_a, res_b selection)
  - Module interface (ports)

You're ONLY replacing the CSA tree instantiations.


HINT 11: Testing Strategy

If your tests fail:
  - Check CSA32 arithmetic first (sum XOR, carry majority+shift)
  - Verify you're unpacking INPUT correctly
  - Make sure carry has the left-shift (missing this breaks everything)
  - Check that Wallace tree topology has enough levels
  - Verify output signal names match what downstream logic expects


HINT 12: Module Organization

It's fine to create separate files for:
  - Your CSA32 building block
  - Your 5→2 Wallace tree module
  - Your 4→2 Wallace tree module

Don't try to cram everything into the main multiplier file. Clean modular design is better.
