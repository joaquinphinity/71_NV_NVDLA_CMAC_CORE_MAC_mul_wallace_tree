REPLACE CSA TREE WITH STRUCTURAL WALLACE TREE

The CMAC multiplier currently uses NV_DW02_tree modules for carry-save adder tree reduction. Replace these with a structural Wallace tree implementation.

Study the NVDLA source code to understand:
- Where the CSA trees are currently used
- What their interface and behavior is
- How to create a functionally equivalent replacement

Place your Wallace tree implementation files in the sources/vmod/nvdla/cmac/ directory (same location as the multiplier you're modifying). This follows NVDLA's organization principle where application-specific modules stay with their parent components, while vmod/vlibs/ is reserved for generic, parameterized library components.

Create as many separate files as you need for your implementation.

Your Wallace trees should match the interface of what they're replacing - same inputs, same outputs, just different internal implementation.

Requirements:
- Drop-in replacement: Produces identical outputs to the original
- All modes work: INT8, INT16, and FP16 modes must continue working
- No new ports: Module interface stays as it is
- Synthesis-friendly: Use structural instantiations, not behavioral loops

Everything you need is in the codebase.
