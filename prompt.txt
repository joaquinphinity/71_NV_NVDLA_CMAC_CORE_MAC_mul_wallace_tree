OPTIMIZE THE CMAC MULTIPLIER WITH A STRUCTURAL WALLACE TREE

The Problem

The CMAC multiplier currently uses generic CSA tree modules that work through behavioral iteration loops. This makes synthesis tool-dependent and timing unpredictable. We want to replace these with an explicit Wallace tree using structural carry-save adder stages for better performance and more reliable synthesis.

Your Task

Replace the iterative CSA tree with a hand-crafted structural Wallace tree in the CMAC multiplier.

You can create as many new RTL modules as you think you need to implement this properly. Don't try to fit everything into a single file - organize your Wallace tree implementation into separate modules however makes sense to you.

What You Need to Know

WALLACE TREE CONCEPT

A Wallace tree is an efficient way to add multiple numbers together using carry-save arithmetic. Instead of adding them sequentially with ripple carries, you reduce them in parallel using small adder units.

The basic building block is a 3-to-2 compressor. It takes three input numbers and produces two outputs: a sum and a carry.

The idea is simple:
  - For each bit position, look at the three input bits
  - The sum bit is what you'd get if an odd number of inputs are 1
  - The carry bit represents the overflow - it's 1 when at least two inputs are 1, and it goes to the next higher bit position (has twice the weight)

To add N numbers with a Wallace tree:
  1. Group them in sets of three
  2. Apply your 3-to-2 compressor to each group  
  3. Now you have fewer numbers (roughly two-thirds as many)
  4. Repeat until you're down to just two numbers (sum and carry)
  5. Those final two get added later in the pipeline

The advantage is that all bit positions work in parallel - no waiting for carries to ripple across.

CARRY-SAVE ARITHMETIC

In carry-save format, you keep sum and carry separate until the very end.

For your 3-to-2 compressor:
  - The sum bit tells you if an odd number of inputs are 1 (like an XOR operation)
  - The carry bit tells you if you had overflow - when 2 or 3 inputs are 1 (like a majority vote)
  - The carry gets added to the next higher bit position (it represents double the weight of the sum bit)

The final sum and carry outputs from your Wallace tree will be combined later in the pipeline - your job is just to reduce many inputs down to those final two.

What to Do

STEP 1: UNDERSTAND THE CURRENT IMPLEMENTATION

Study the CMAC multiplier code. Look for where the CSA trees are currently used. You'll find they take partial products (generated from Booth encoding) and reduce them down.

Analyze the code to understand:
  - How many partial products are there?
  - How are they organized?
  - How many CSA tree instances exist?
  - What's the interface of each tree?
  - How does the data flow through the multiplier?

STEP 2: IMPLEMENT YOUR WALLACE TREE

Create the modules you need to implement an efficient Wallace tree. You might want:
  - A basic 3-to-2 compressor module (your building block)
  - Wallace tree modules that reduce multiple inputs to two outputs
  - Any helper modules that make sense for your design

Organize them however you think is cleanest. Create as many separate files as you need.

Your Wallace trees should match the interface of what they're replacing - same inputs, same outputs, just different internal implementation.

STEP 3: REPLACE THE GENERIC TREES

Swap out the old CSA tree instantiations with your new Wallace tree modules.

Everything else - Booth encoding, mode logic, control signals, output formatting - stays exactly the same. You're only changing how partial products get summed up.

Requirements

  - Drop-in replacement: Produces identical outputs to the original for all inputs
  - All modes work: The multiplier supports three different operating modes - all must continue working
  - No new ports: Module interface stays exactly as it is
  - No pipeline changes: Keep the same combinational structure
  - Synthesis-friendly: Use explicit structural instantiations, not behavioral loops

What to Figure Out

The complete NVDLA source code is provided for context. Everything you need to know about interfaces, data flow, operating modes, and integration requirements is in the codebase.

Study the code to understand:
  - Where and how the CSA trees are currently used
  - What interface your Wallace tree modules should have
  - How the three operating modes (INT8, INT16, FP16) work
  - What the data flow looks like from partial products to outputs
  - Which parts of the code to keep versus which to replace

Take your time to analyze and understand the patterns. The implementation will follow naturally once you understand the existing structure.

Everything you need is in the codebase. The tests will verify your implementation is functionally equivalent to the original while providing the better synthesis characteristics we're looking for.
