OPTIMIZE THE CMAC MULTIPLIER WITH A STRUCTURAL WALLACE TREE

The CMAC multiplier currently uses generic NV_DW02_tree modules for CSA reduction. Replace these with structural Wallace tree implementations for better synthesis predictability and performance.

Study the NVDLA source code to understand the current architecture and determine your replacement strategy.

Requirements

Your Wallace tree implementation must:
  - Produce functionally equivalent outputs to the original NV_DW02_tree
  - Support all three operating modes (INT8, INT16, FP16)
  - Use structural instantiations (no behavioral loops)
  - Maintain the same module interface (no new ports)

File Organization

Place your Wallace tree implementation files in the sources/vmod/nvdla/cmac/ directory (same location as the multiplier you're modifying). This follows NVDLA's organization principle where application-specific modules stay with their parent components, while vmod/vlibs/ is reserved for generic, parameterized library components.

Create as many separate files as you need for your implementation.

Your Wallace trees should match the interface of what they're replacing - same inputs, same outputs, just different internal implementation.

Implementation

Analyze the codebase to determine:
  - Which modules need to be replaced
  - What the module interfaces should be
  - How to structure your Wallace tree reduction
  - How the three operating modes work

The complete NVDLA source code is provided for context. Study the existing code to understand the architecture, data flow, and integration requirements.
